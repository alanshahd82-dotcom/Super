# SUPER VOICE CHAT — PROJECT CONTEXT

Last updated: 2026-10-02

## 1. الهدف الأصلي غير القابل للنسيان

هذا المشروع ليس مجرد chatbot.

الهدف هو إنشاء **دردشة واحدة قابلة للتثبيت كتطبيق PWA على الهاتف والحاسوب**، تكون واجهة تحكم لوكيل يستطيع تطوير نفسه والمشروع الذي يعيش فيه بأوامر المستخدم النصية أو الصوتية.

أمثلة على المطلوب من داخل الدردشة:
- "حسن شكل الدردشة."
- "أضف كاميرا."
- "أضف قاعدة بيانات."
- "أضف تكاملاً."
- "أنشئ صفحة جديدة."
- "اقرأ ملفاتك، عدلها، اختبرها، ثم انشرها."

المستخدم لا يجب أن يحتاج للدخول إلى الكود لكي يطور التطبيق.

## 2. القيود الأساسية

- الأولوية: 0 درهم تشغيل أساسي.
- لا API مدفوع.
- لا اشتراك مدفوع مطلوب للدردشة الأساسية.
- لا رصيد رسائل مرتبط بمزود نموذج خارجي في المسار الأساسي.
- النموذج الأساسي مفتوح المصدر ويعمل محلياً عند الحاجة.
- التطبيق يجب أن يعمل من الهاتف والحاسوب.
- التطبيق يجب أن يكون قابلاً للتثبيت PWA.
- GitHub هو مخزن المشروع ومصدر النشر.
- لا تضع GitHub token أو أسرار أو كلمات مرور داخل المستودع العام أو كود الواجهة.
- العمليات الحساسة جداً (مثل حذف المستودع أو كشف أسرار) لا تنفذ تلقائياً بلا تأكيد صريح.

- repo_tree

دورة العمل الدائمة أصبحت متعددة الخطوات: يستطيع الوكيل استعراض شجرة المشروع، البحث عن رمز/نص، قراءة الملفات، ثم بناء التعديل. القراءة تعيد HEAD الحالي، والكتابة لا تُقبل إلا إذا كان HEAD المتوقع مطابقاً حتى لا يكتب فوق تغيير أحدث.

التغييرات المحلية يمكن حفظها في المتصفح.
التغييرات الدائمة تمر عبر Agent Bridge إلى GitHub.

### Agent Bridge
المجلد:
- agent-bridge/

الملفات:
- agent-bridge/server.mjs
- agent-bridge/start-bridge.ps1
- agent-bridge/watch-bridge.ps1

وظيفته:
1. استعراض ملفات voice-chat عبر repo_tree.
2. البحث داخل المشروع عبر repo_search.
3. قراءة الملفات عبر repo_context.
4. قبول تغييرات محدودة داخل voice-chat فقط.
5. رفض الكتابة إذا لم تكن مبنية على HEAD تمت قراءته أو إذا تغير المستودع بعد القراءة.
6. التحقق من syntax لملفات JavaScript.
7. التحقق من JSON/manifest.
8. تشغيل git diff --check.
9. إضافة سجل لكل تغيير فعلي في voice-chat/AGENT_HISTORY.jsonl.
10. Commit.
11. Push إلى main.
12. إنشاء deploy-state.json بمعرّف نشر فريد لكل تغيير.
13. بعد Push، ينتظر الجسر حتى يرى نفس معرّف النشر على GitHub Pages ليتأكد أن النسخة الحية وصلت فعلياً.
14. إذا فشل Push بعد Commit، يعاد المستودع تلقائياً إلى HEAD السابق بدلاً من ترك حالة نصف منشورة.

الجسر يستمع محلياً على:
- http://127.0.0.1:8788

ويتم الوصول إليه من الهاتف عبر Cloudflare Tunnel مجاني.

## 5. الأمان

- التوكن السري محفوظ محلياً خارج المستودع:
  %LOCALAPPDATA%\SuperVoiceAgent\bridge-secret.json
- لا يتم نشر التوكن إلى GitHub.
- الربط من الهاتف يتم برمز pairing مؤقت.
- Origin المسموح الرئيسي:
  https://alanshahd82-dotcom.github.io
- الكتابة مقيدة حالياً بمسارات voice-chat/ فقط.
- الملفات الحساسة مثل .env / secrets / credentials / tokens محمية من الكتابة عبر bridge.
- iframe extensions معزولة sandbox.

## 6. الاستمرارية

- start-bridge.ps1 يشغل الجسر والنفق.
- watch-bridge.ps1 يراقب كل دقيقة ويعيد التشغيل عند الحاجة.
- Startup shortcut يشغل watchdog عند تسجيل الدخول إلى Windows.
- bridge-endpoint.json يحمل رابط النفق الحالي.
- إذا تغير Quick Tunnel، start-bridge.ps1 يحدث bridge-endpoint.json ويدفع التغيير إلى GitHub تلقائياً.

ملاحظة: Quick Tunnel مجاني لكنه ليس خدمة لها ضمان uptime دائم. هو حل مجاني تشغيلي، وليس ضماناً تعاقدياً بلا حدود.

## 9. الأولوية التالية

لا تعِد بناء ما سبق.

المرحلة التالية هي تحسين جودة الوكيل نفسه بحيث:
1. يفهم أوامر التطوير بشكل أفضل.
2. يقرأ PROJECT_CONTEXT.md دائماً قبل أي تعديل دائم.
3. يختار الملفات الصحيحة تلقائياً.
4. يستخدم تعديلات جراحية بدلاً من إعادة كتابة ملفات كاملة عندما يمكن.
5. يختبر النتيجة قبل النشر.
6. يبلغ المستخدم بنتيجة حقيقية: ما الذي تغير، هل نجح الاختبار، وما commit المنشور.
7. يحتفظ بسجل تغييرات وذاكرة مشروع واضحة.

## 10. قاعدة السياق

قبل أي repo_patch أو repo_write:
- اقرأ هذا الملف أولاً.
- لا تغير الهدف الأصلي.
- لا تستبدل المسار المجاني الأساسي بخدمة مدفوعة دون موافقة صريحة.
- لا تعد بحثاً أو إعداداً تم إثباته هنا.
- إذا وجد خطأ، أصلح الخطأ المحدد بأقل تغيير ممكن ثم اختبر.

هذا الملف هو handoff دائم للمشروع، ويجب تحديثه بعد أي تغيير معماري مهم.
